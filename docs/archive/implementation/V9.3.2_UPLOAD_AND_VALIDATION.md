# V9.3.2 Upload and Validation

## Patch type

The V9.3.2 deliverable is an overlay patch against the current V9.3.1 `main` repository. It contains only files that changed or were added. Extract the ZIP locally, then upload the extracted directory structure at the repository root. Replace matching files and add the new files. Do not delete unrelated repository files.

## Release identity

- Release: `9.3.2-browser-qa-ranking-integrity`
- Runtime: `9.3.2-foundation`
- Value Finder: `9.3.2-VF4`
- Stage: `release-candidate`
- Local deterministic release gate: `DEPLOYABLE_SOURCE`
- Browser preview is still required before promoting to production.

## GitHub Actions sequence

### 1. Validate FIE V9.3.2 Browser QA

Open GitHub -> Actions -> **Validate FIE V9.3.2 Browser QA** -> Run workflow.

Required result:

- workflow green
- `STATUS: DEPLOYABLE_SOURCE`
- all V9.3.2 structural/source/browser/season checks PASS

The workflow produces a validation artifact named approximately `fie-v9.3.2-validation-<commit>` containing the gate, manifest, generated release descriptors and deployable `dist/` output.

### 2. Refresh FIE Current Season

After the first validation is green, open **Refresh FIE Current Season** and run it with:

- League ID: blank
- Season: blank
- Week: blank
- Governance mode: `KEEP`

This refreshes every enabled managed league. Leaving Season and Week blank is intentional. V9.3.2 resolves the real Sleeper league season and no longer allows a blank/zero browser selector to create Season 0.

The corrected current-snapshot builder uses the same structural-v2 fingerprint contract as the stored league profile. The offline captured-live regression already matches 19/19 managed league profiles; the connected refresh should therefore remove false profile mismatches unless a league has genuinely changed structurally.

### 3. Validate FIE V9.3.2 Browser QA again

Run the V9.3.2 validation workflow a second time after Refresh Current commits its generated data.

Required result again:

- `STATUS: DEPLOYABLE_SOURCE`
- all checks PASS
- current-storage integrity PASS for all managed leagues

## Do not run M1-M6 by default

Do not rebuild historical M1-M6 simply for this release. If a league still reports a real structural/profile mismatch after the corrected Current refresh, inspect the structural-diff reason and rebuild only that affected league if necessary.
