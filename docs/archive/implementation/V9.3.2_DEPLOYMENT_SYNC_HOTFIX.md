# V9.3.2 Deployment Synchronization Hotfix

## Root cause

Cloudflare Pages is configured by `wrangler.toml` with `pages_build_output_dir = "dist"`. The repository source on `main` was updated to V9.3.2, but the first V9.3.2 changed-files overlay omitted the generated `dist/` tree.

The successful validation workflow ran `python tools/release_build.py --mode personal` inside its temporary runner and uploaded the generated `dist/` as an Actions artifact. It had read-only repository permission and therefore did not commit that generated deploy tree. The Current Season workflow refreshed `data/research/...` in the source tree but also did not rebuild `dist/`.

Consequently source and deployed artifacts diverged:

- source `app/generated/release.js`: V9.3.2;
- tracked `dist/app/generated/release.js`: V9.3.1;
- source Genesis current snapshot: refreshed 2026 snapshot with `profile_current_match=true`;
- tracked deployed Genesis current snapshot: older snapshot with `profile_current_match=false`;
- V9.3.2 core files such as `dist/app/core/numeric.js` were absent.

This explains all three browser symptoms together: V9.3.1 title, Season 0, and old zero/null weekly behavior.

## Permanent behavior

1. **Rebuild FIE Deploy Dist** can regenerate and commit the deployment tree at any time.
2. **Refresh FIE Current Season** now rebuilds and commits deployment output after a data refresh.
3. **Validate FIE V9.3.2 Browser QA** now fails if tracked `dist/` is stale, so a green validation means the committed Cloudflare payload actually matches the validated source.

## Recovery sequence

After uploading this hotfix:

1. Run **Rebuild FIE Deploy Dist**.
2. Wait for its commit to `main` and Cloudflare deployment.
3. Run/confirm **Validate FIE V9.3.2 Browser QA** is green. It may auto-run from the generated-file commit.
4. Hard-refresh the application once.

There is no need to rerun M1-M6 or Refresh Current immediately: the source-side Current refresh already completed successfully.
