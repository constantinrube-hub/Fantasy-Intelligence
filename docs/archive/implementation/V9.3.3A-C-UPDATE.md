# Fantasy Intelligence Engine V9.3.3A-C

Date: 2026-08-27
Patch target: current GitHub `main` reviewed on 2026-08-27

This patch is a runtime-integrity stabilization before the larger V9.4 consolidation audit. It is intentionally small: one existing hydrator is replaced, one additive runtime module is introduced, and one focused validation test/workflow is added.

## V9.3.3A, State and data integrity

### Cross-league Command Center / Matchup contamination

A guard now owns `FIEDecisionEngines.leagueSim` publication. A completed asynchronous simulation is rejected when its league ID does not equal the active/switching league, and a completed simulation is rejected when its week no longer equals the selected week. League changes and week changes clear the prior simulation immediately.

Expected result: Genesis simulation or matchup values cannot appear after switching to Chopped, even when the Genesis calculation finishes late.

### Missing projection is no longer zero

`app/current-snapshot-store.js` no longer hydrates an absent projection overlay as `[0, 0]`. Missing decision and Sleeper projections remain `null`.

The selected-week fast path follows the same contract:

- valid projection: numeric value
- verified bye: real `0`
- missing projection: `null` / unavailable

Expected result: players such as Chase, Shaheed or Tonges are no longer silently assigned a fabricated weekly zero merely because a projection row failed to match.

### Canonical season

Invalid or missing league/weekly season values, including `0`, are repaired from the canonical season resolver. The season selector is synchronized to that value.

Expected result: no `Season 0` in normal loaded-league views.

### Player-name repair

Players with an empty display name are repaired from the Sleeper player map before weekly/Command Center rendering.

Expected result: O/Q lineup alerts identify the player rather than showing a status without a name when Sleeper identity data exists.

## V9.3.3B, Fast switching and enrichment behavior

### Snapshot-first league switching

The existing generated per-league `app/core.json` snapshot path is now attempted for every Sleeper league/roster/user read, not only after the background league-index prefetch has already registered that league ID.

The browser refreshes the generated snapshot at most once per day. A league switch does **not** automatically trigger an additional Sleeper live roster refresh. Existing explicit/manual refresh paths can still use `FIEDataClient.refreshLeague`.

Expected result: a prefetched/generated league behaves much more like opening another tab, while roster/transaction freshness can be refreshed deliberately rather than making every switch expensive.

### NFL schedule fast path

The season schedule is fetched once through the existing `/api/data/nflverse/schedule` proxy and cached. Opponent resolution for all weekly surfaces uses the selected season/week schedule.

Expected result: Week 1 to Week 2 opponent changes do not require a new large enrichment cycle.

### Selected-week projection fast path

Changing week fetches only `/api/data/sleeper/projections/{season}/{week}` through the existing cached data layer. It updates player projection, opponent and uncertainty fields for that selected week and then recalculates league scoring.

Expected result: week changes are lightweight and actually change weekly opponent/projection context where Sleeper publishes the data.

### Enrichment render coalescing

During automatic public enrichment, repeated background `render()` and `updateKPIs()` calls are coalesced. User interactions still bypass the gate, so tab navigation remains responsive. When enrichment finishes, one coherent final render is flushed.

Expected result: Power Rankings should not visibly bounce through every intermediate enrichment state, and repeated whole-app rerenders should consume less CPU.

Important: this reduces browser/render cost. It does not claim that every legacy enrichment calculation itself has been eliminated. The V9.4 performance audit should profile remaining long tasks after this patch.

## V9.3.3C, Weekly / D/ST / Kicker UX

### Matchup and playoffs week selector

A visible `Matchup / playoffs week` selector is inserted into the Matchup & Playoffs engine. It changes the global selected week, selected-week projections, opponents and simulation start week.

### D/ST and Kicker opponents

The season schedule fast path supplies opponent/bye context to the existing D/ST and Kicker intelligence modules. Unknown schedule remains `—`; a verified no-game week becomes `BYE`.

### Next 3 naming

`Next 3` is relabelled `Next 3 Avg` for D/ST and Kicker. It remains the mean of up to the next three available weekly projections from the selected week.

### Low / High semantics

Special-teams `Low / High` is explicitly labelled as empirical only when a governed calibrated interval exists. Otherwise it is a heuristic range and **not** called P10/P90.

The split-current hydrator additionally rejects suspicious repeated D/ST/K uncertainty signatures when the same exact interval is repeated across a large share of the position group. Those values become unavailable instead of being presented as empirical uncertainty.

## Deployment

Copy the files above into the same paths in the current repository. Do not replace the repository with an older ZIP.

After upload:

1. Run **Validate FIE V9.3.3A-C**. It must finish green.
2. Run the existing **Refresh FIE current season** workflow so current per-league artifacts are fresh.
3. Run the existing V9.3.1 / current repository validation workflow that was previously green.
4. Let Cloudflare Pages deploy the updated `main` branch.
5. Hard refresh the browser once so the new static JS file is loaded.

## Browser acceptance test

Use Genesis first, then Chopped.

1. Load Genesis. Confirm season is 2026 rather than 0.
2. Open Weekly Projections. Confirm `Opp` contains a team or `BYE` when schedule is published.
3. Check previously problematic players. A missing projection must display unavailable rather than a fabricated 0.0. A genuine bye may be 0.
4. Change Week 1 to Week 2. Confirm opponent/projection context updates without waiting for full Public Enrichment.
5. Open Matchup & Playoffs. Confirm the new visible week selector exists and changing it reruns the correct week.
6. Open D/ST and Kicker. Confirm opponents appear where schedule exists; confirm `Next 3 Avg`; confirm Low/High carries the new semantics.
7. While Public Enrichment is still running, switch through Team, Weekly, Draft, D/ST and Kicker. Navigation should remain usable.
8. Note Genesis Power Rankings during enrichment. They should remain stable through intermediate background renders and update coherently at publication/final render.
9. Switch Genesis to Chopped while Genesis enrichment/simulation is still active. Confirm no Genesis team name, projected score, matchup or playoff probability appears in Chopped.
10. Switch back to Genesis. A generated/prefetched league should use the snapshot fast path rather than rebuilding the whole league shell from scratch.
