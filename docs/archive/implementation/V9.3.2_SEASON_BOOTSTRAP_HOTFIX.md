# V9.3.2 Season Bootstrap Hotfix

## Browser symptom

After the synchronized V9.3.2 deployment, the application could fail during staged Sleeper league loading with:

`League universe build failed: activeSeason is not defined`

## Root cause

`buildPlayerUniverse()` lives in the first classic inline application script and calls `activeSeason()` while constructing player entry classes. V9.3.2's Season-0 fix defined `activeSeason()` only later inside the private V8.9 compatibility IIFE. The algorithm itself was correct, but the binding was not visible to the earlier script/runtime path. The previous season test extracted and executed the later helper in isolation, so it validated the algorithm but not real browser script ordering/scope.

## Fix

- Added `app/core/season-context.js` as the strict season parser/resolver.
- Load the season context before the first inline application script.
- Define/expose the bootstrap `activeSeason()` binding before `buildPlayerUniverse()` can execute.
- Keep loaded Sleeper league season authoritative.
- Reject null, blank, `0`, and `"0"` as invalid NFL seasons.
- Make the later V8.9 compatibility layer delegate to the global season API instead of defining a second algorithm.
- Make M5 current compatibility use the canonical active season instead of independently coercing the selector.
- Added the season service to the build manifest.
- Strengthened the existing V9.3.2 season regression to assert actual service/script ordering and global scope. It now fails if `activeSeason()` appears after `buildPlayerUniverse()`.
