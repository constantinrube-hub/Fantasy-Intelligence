# Fantasy Intelligence V9.3.4A-B

Base repository commit: `dbe35983a9932a4e5ba540dc4606e5f4215055cb`

## Scope

This patch implements the agreed V9.3.4A Performance Rescue and V9.3.4B Correctness Quick Wins. It deliberately does not implement the later matchup service, universal starter-slot valuation layer, or expanded return-opportunity model.

The later V9.3.4D valuation work must treat starter-slot economics as a universal league principle. Chopped exposed the issue, but replacement value, eligible starter paths, FLEX/SF access, starter demand and marginal lineup utility apply to every format.

## V9.3.4A: Performance Rescue

### 1. Cold-load critical path

The current league controller waits for the full Sleeper NFL player map before declaring the core league shell ready. On a fresh browser this can dominate first load time.

V9.3.4A adds a prebuilt shared compact player catalog:

- Generated by `research/build_league_app_snapshots.py`.
- Stored at `data/research/app/player-catalog.json`.
- Contains only the fields required by the browser player universe, identity and injury UI.
- Validated fail-closed before publication.
- Preserves the last-known-good catalog if a refresh fails.
- Referenced by every generated league core and by the league index.
- Copied into Cloudflare `dist` by `tools/sync_league_app_snapshots.py`.
- Primed by the browser before `FIELeagueController.switchLeague` proceeds.
- Falls back to the legacy full Sleeper player endpoint if the compact artifact is unavailable.

### 2. Public enrichment main-thread work

The old public enrichment path fetched and parsed four large CSV feeds, then performed player, contract, production and snap matching on the main thread. Contract matching was especially inefficient because it repeatedly scanned the complete contract table for every player.

V9.3.4A now:

- Parses large CSV payloads in `app/workers/csv-parse-worker.js`.
- Uses cached text through the existing centralized data client.
- Builds indexed contract lookups once instead of repeatedly filtering the complete contract table.
- Processes large row sets cooperatively, yielding between chunks.
- Uses prior-season nflverse production/snaps dynamically.
- Checks the active league context between chunks and stops publishing if the user has switched leagues.

### 3. Atomic enhancement publication

League enhancements are now serialized into coherent stages:

1. Season projections
2. Governed research/current features
3. Public enrichment
4. One atomic score publication

Player changes from each background stage are captured into staging state while the previously published player state remains available to the UI. Automatic `assignScores` calls from intermediate legacy stages are deferred. The combined staged state is published once, then the canonical scoring pass runs once and cached draft/value services are invalidated.

This is intended to stop Power Rankings and other score-driven views from walking through multiple intermediate ranking states during public enrichment.

### 4. Navigation during enrichment

Automatic renders remain coalesced during enrichment, but explicit user navigation receives render tickets so tab changes can still render. Heavy CSV parsing is moved off the main thread and large enrichment loops yield cooperatively.

### 5. Week switching

Normal week changes no longer trigger the full league simulation by default.

- Selected-week projections and schedule context use the fast path.
- Full `assignScores` is deferred until the browser is idle and the context is still current.
- The full league simulation is reserved for the matchup simulation surface or an explicit simulation request.

This targets the measured 45-second Week 1 to Week 2 change without removing the deeper simulation capability.

## V9.3.4B: Correctness Quick Wins

### NFL team aliases

Schedule matching now canonicalizes common feed aliases, including:

- `LA`, `LAR`, `STL` -> `LAR`
- `JAC`, `JAX` -> `JAX`
- `WSH`, `WAS` -> `WAS`
- `OAK`, `LV` -> `LV`
- `SD`, `LAC` -> `LAC`

Additional historical/provider aliases are normalized for SF, GB, KC, NE, NO and TB.

This addresses the confirmed Rams false-BYE case.

### D/ST and Kicker first-render Next 3

The selected week plus the next two weeks are preloaded before the first D/ST or Kicker board is presented as ready. Until that window is ready, the specialist surface displays a loading state rather than a misleading Next-3 average built from repeated current-week baseline values.

### Draft Start/Sit panel leak

`#fie93WeeklyPanel` is now visible only when the active surface is `startsit`. Draft Board and all other tabs explicitly receive the hidden state through the central DOM enhancer.

### League-aware position filters

The shared position selector is rebuilt from `FIELeagueContext.current().legalPositions`, canonicalized and ordered. Positions that the league cannot roster are not offered as filters.

## Deployment sequence

1. Apply the eight changed/new repository files from this package to the current `main` based on the commit listed above.
2. Commit/push the source changes.
3. Let or manually run **Validate FIE V9.3.4A-B**. Both the V9.3.3 compatibility test and the V9.3.4A-B contract test must pass.
4. Manually run **Refresh FIE Current Season** once, with League ID blank if you want all managed league snapshots refreshed. This creates `data/research/app/player-catalog.json`, rebuilds league core references, validates the generated artifacts, rebuilds `dist`, and commits the synchronized deployment tree.
5. Wait for Cloudflare Pages to deploy the resulting `dist` commit.
6. Perform the browser QA below before declaring the performance rescue complete.
