# FIE V9.3.4A2 Hotfix

## Why this patch exists

Browser QA after V9.3.4A-B showed two remaining performance defects:

- Genesis still took roughly three minutes before the league was fully loaded.
- Genesis to Chopped took roughly 50 seconds before the Chopped workspace appeared, then roughly another 45 seconds for enrichment. During that Chopped enrichment the page could become sluggish or effectively frozen.
- Public Data could correctly show 3/4 while the separate Public Enrichment counter remained at 0/4.

The current runtime foundation still performs `buildPlayerUniverse`, `populateDraftControls`, `assignScores`, `updateKPIs`, and `render` inside the league-switch critical path. The existing V9.3.4 enrichment layer then performs another score publication after its staged enhancement work. A2 removes the avoidable work from the first-paint path without replacing the large generated shell.

## What A2 changes

### 1. Core league switch becomes first-paint first

During the league switch only the minimum workspace is constructed. Shell scoring, KPI recomputation, automatic render churn, and non-visible Draft controls are deferred. After the first browser paint, one coherent render is allowed and the app emits `fie:core-interactive`.

The enhancement pipeline is then launched from an idle slot, outside the switch critical path.

### 2. Player universe is reduced before `buildPlayerUniverse`

The full compact catalog remains cached, but the hot-path universe passed into `buildPlayerUniverse` contains only:

- positions actually relevant to the active league,
- current active NFL players,
- relevant injured/current-team players,
- sufficiently relevant ranked current players,
- every rostered, starter, reserve, and taxi player regardless of status.

The full player map is restored immediately after universe construction, so identity lookup and later repair still retain the complete catalog.

This is especially important for non-IDP leagues such as Genesis and Chopped because historical inactive and irrelevant defensive-player records no longer participate in every league rebuild.

### 3. Draft initialization is lazy

`populateDraftControls()` is skipped when Draft is not the visible tab. If Draft is already active, or the user opens Draft, the original controls are initialized normally.

This is specifically intended to remove unnecessary drafting-state work from the Genesis to Chopped switch.

### 4. Public Enrichment counter now follows the real sources

A2 wraps the existing four nflverse CSV requests:

- players,
- contracts,
- stats,
- snaps.

As each source resolves, `state.publicStatus` is updated immediately and the visible Public Enrichment counter is repaired from the canonical state. It no longer has to remain at 0/4 until the whole enrichment promise settles.

At the enhanced event the counter is treated as complete even when the result is 3/4 because one unavailable source must not look like an endless loading state.

### 5. Performance instrumentation

A2 records:

- core interactive time,
- player-universe build time and before/after catalog size,
- filter and roster-picker time,
- Draft-control time,
- scoring time,
- KPI time,
- render time,
- public source settlements/failures,
- all functions taking more than 250 ms.

In the browser console run:

```js
FIE934A2.report()
```

The same measurements are also pushed into the existing `FIEPerformance` collector under the `934a2:` prefix.

## Deployment

Upload the patch preserving paths. Then run:

1. `Validate FIE V9.3.4A2`
2. `Refresh FIE current season`
3. the existing V9.3.1/V9.3.4 validations you normally use
4. let Cloudflare Pages deploy
5. hard refresh the app

## Browser acceptance test

### Genesis cold load

1. Hard refresh.
2. Open Genesis.
3. Measure time until tabs can be changed and the league name/rosters are visible.
4. Do not wait for Public Enrichment to finish before testing navigation.
5. Verify the Public Enrichment count advances when individual public sources finish.

### Genesis to Chopped

1. From loaded Genesis, switch to Chopped.
2. Measure time until Chopped is visible and tabs respond.
3. Change tabs repeatedly while enrichment is still running.
4. Open Draft and verify Draft controls initialize then, not before.
5. Verify no Genesis names, rosters, matchups, or rankings appear in Chopped.

### Diagnostics

After each switch run:

```js
FIE934A2.report()
```

The most useful fields are:

- `diagnostics.coreInteractiveMs`
- `diagnostics.playerMapBefore`
- `diagnostics.playerMapAfter`
- `diagnostics.timings`
- `diagnostics.longFunctions`
- `diagnostics.lastPublic`

## Expected effect

This patch is designed to reduce time-to-interactive much more aggressively than V9.3.4A-B. It does not claim that all background enrichment will finish within a few seconds. The key acceptance condition is that a prefetched/cached league becomes usable quickly and remains usable while enrichment continues.

Target after A2:

- warm/prefetched league core: <= 2 seconds p95 eventually,
- cold core: <= 5-10 seconds,
- tab navigation during enrichment: responsive,
- Public Enrichment counter: agrees with actual source state,
- no automatic Draft initialization when Draft is not open.
