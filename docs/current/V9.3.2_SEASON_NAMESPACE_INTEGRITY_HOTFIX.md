# V9.3.2 Season Namespace Integrity Hotfix

## Root cause

Three public globals had accidentally been treated as one concept. Before the V9.3.2 Season-0 repair, `runtime-foundation.js` already owned `window.FIESeasonContext` as a runtime facade exposing `active()`, `prior()`, `next()`, `week()` and `snapshot()`. The new browser-QA repair introduced an early strict season resolver and also published it as `window.FIESeasonContext`, with a different API exposing `parse()`, `fallback()` and `resolve()`. During startup the early object was later overwritten by runtime-foundation.

This explains the sequence of browser errors:

1. `activeSeason is not defined`: V9.3.2 made early league-universe code use `activeSeason()` while that helper still lived only inside the later compatibility scope.
2. `FIE season context is unavailable`: the first scope hotfix moved `activeSeason()` early, but it depended on `FIESeasonContext.resolve`. By the time league loading executed, runtime-foundation had installed its pre-existing facade at the same global name, which did not expose `resolve()`.
3. `window.FIESeasonContext.resolve is not a function`: the fallback hotfix ensured an early resolver existed, but runtime-foundation still overwrote it later. The more direct call exposed the underlying namespace collision explicitly.

## Fixed ownership

- `window.FIESeasonBootstrapResolver`: strict early startup fallback only.
- `window.FIECore.SeasonResolver`: canonical strict resolver after `numeric.js` loads.
- `window.FIESeasonContext`: runtime facade only. It now also provides a compatibility `resolve()` delegate for stale-cache rollover safety.
- `window.activeSeason()`: stable public function that prefers `FIECore.SeasonResolver` and falls back to `FIESeasonBootstrapResolver`. It never depends on the runtime facade namespace.

## Deployment cache hardening

`index.html`, `/app/*`, and the critical season/numeric/runtime script URLs are revalidated/cache-busted so a deployment is less likely to combine a new HTML shell with old JavaScript.

## Regression coverage

The season runtime test now executes all three startup phases and explicitly overwrites `FIESeasonContext` with the older runtime-facade shape lacking `resolve()`. `activeSeason()` must continue returning 2026. This reproduces the exact live failure rather than merely unit-testing the season arithmetic.
