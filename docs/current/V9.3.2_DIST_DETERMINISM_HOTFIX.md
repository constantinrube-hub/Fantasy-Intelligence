# V9.3.2 Dist Determinism Hotfix

## Symptom

`Rebuild FIE Deploy Dist` completed successfully, but the immediately triggered V9.3.2 validation failed with only:

```text
M dist/config/build-manifest.json
```

## Root cause

`research/build_app_manifest.py` used the current wall-clock time for `generated_at`.

The deploy workflow therefore committed one timestamp. The validation workflow then ran the same deterministic release build a few moments later, generated a different timestamp, copied that new manifest into `dist/`, and correctly detected a Git diff.

The gate was therefore impossible to satisfy even when source, research data and every actual deployed runtime asset were unchanged.

## Fix

`generated_at` now uses `config/release.json -> built_at`, the canonical release timestamp. This keeps the field meaningful while making repeated builds of the same release byte-stable.

A new `integrity_v932_build_determinism_test.py` runs the manifest builder twice, requires identical results, requires `generated_at == release.built_at`, and rejects reintroduction of a wall-clock `datetime.now()` timestamp.

The regression is part of `research/release_gate.py`.

## Required deployment sequence

1. Apply this patch to `main`.
2. Ignore the expected validation failure caused by the source patch making the old committed `dist/` stale.
3. Run **Rebuild FIE Deploy Dist** once.
4. Allow the follow-up **Validate FIE V9.3.2 Browser QA** run to execute.
5. The `dist/` synchronization step should now report `PASS committed dist/ matches deterministic release build`.

No Current Season refresh is required for this CI/build-system hotfix.
