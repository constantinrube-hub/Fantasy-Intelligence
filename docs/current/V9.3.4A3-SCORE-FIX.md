# Fantasy Intelligence V9.3.4A3 Score Performance Fix

## Why this patch exists
V9.3.4A2 browser diagnostics proved that league switching itself is now fast: Genesis reached the interactive shell in 236 ms and Chopped in 338 ms. The remaining freeze was the final `assignScores()` publication: 19.63 s for Genesis and 7.09 s for Chopped.

The source of the cost is repeated full-pool work inside the legacy/V8.9 score stack. Marginal starter demand rebuilt and resorted position pools repeatedly, season decision ranks resorted the eligible pool for each player, and weekly feature helpers repeatedly scanned the same historical rows.

## A3 changes
1. Replaces the hot `assignScores()` path with a formula-compatible accelerated kernel. The old implementation remains available as a fail-safe fallback.
2. Computes starter-slot demand once per score cycle. This is league-specific for every format and includes FLEX, Superflex, IDP flex, K and D/ST economics.
3. Indexes ownership and replacement pools once per position.
4. Computes projection ranks and market edges with one sort.
5. Builds weekly player/history indexes once per prediction cycle and reuses cached recent-form, snap, matchup, team, market and weather context.
6. Applies risk residual quantiles once per position instead of once per player.
7. Computes V8.9 decision rank with one sort, preserving the existing player-decision-value and market-edge formulas.
8. Removes retrospective feature-model training from the synchronous score publication. Existing learned coefficients are still consumed; training remains available through the feature/explicit weekly analysis path.
9. Fixes A2's lean player catalog so leagues with DEF/DST retain free-agent team defenses, not just already-rostered defenses.
10. Repairs `/api/data/nflverse/contracts`: nflverse no longer publishes the old uncompressed `historical_contracts.csv`; the exact Pages Function now fetches `historical_contracts.csv.gz`, decompresses it server-side and returns normal CSV to the existing browser parser.

## Browser QA
Load Genesis, then Chopped. The league shell should remain near A2 performance. After Public Enrichment reaches completion, run:

```js
FIE934A3.report()
```

or the combined report:

```js
FIE934A2.report()
```

The latter now includes an `a3` section.

Key value: `diagnostics.lastTotalMs`. The immediate objective is to reduce the 19,630.8 ms / 7,085.3 ms score publication to well below 1 second, with 500 ms as the A3 target. Browser hardware and the active league still determine the actual result.

Also verify that Public Data reaches 4/4. The contracts endpoint should no longer return 404.

## Fail-safe behavior
If the accelerated scoring kernel throws, A3 records the error in `FIE934A3.report().diagnostics.errors`, increments `fallbacks`, and executes the previous scoring implementation. This favors correctness over performance if an unexpected runtime shape is encountered.
