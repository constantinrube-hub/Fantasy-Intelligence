## Implemented behavior

1. Blank target weeks resolve from a fetched or explicit nflverse regular-season schedule, not the modal stored snapshot week or a separate Sleeper state default. Both producers use the same resolver.
2. The operational week ends at Eastern midnight after its last scheduled game day; advancement additionally requires observed final result/score fields. A late or unresolved prior game blocks automatic advancement. First kickoff does not end the week.
3. The resolver uses timezone conversion across DST and requires all 18 regular-season weeks. Missing/truncated/wrong-season schedules and post-season inference fail closed. Explicit historical weeks require no schedule fetch. An expanded future season must update this operational contract alongside the shared calendar.
4. January closeout resolves to the preceding NFL season. Workflow dispatch can override season/week; automatic runs no longer hardcode 2026.
5. Snapshot/profile/current/app scoring mismatches retain blockers. A week-mismatched Weekly Actions league row identifies the requested week and separately records the observed input week.
   Window 1D now independently validates live state with the same canonical research contract used by Current Snapshot. Waiver timing changes and omitted-versus-zero `best_ball` no longer falsely invalidate historical research. Recognized roster evolution or passive reserve growth cannot bypass simultaneous scoring or other research-contract changes. Full structural fingerprints remain diagnostics; live budget/adds guards remain in the existing planner.
6. Readiness metadata includes profile and snapshot hashes, scoring signatures, source errors, input week/time, snapshot age, global eligible-row counts and model-position coverage where hydrated inputs exist.
7. Summaries separate ready, partial, blocked, not-applicable and unknown results. Lineup capability and execution context remain separate from waiver capability. Not-applicable or unknown reports are not counted as ready.
8. Each workflow summarizes the exact output generated by that invocation and commits its resolved season directory. An unrelated report with a newer filesystem timestamp cannot be selected.
9. A green workflow can still preserve a blocked research report or useful raw waiver history. The artifact summary states its evidence status explicitly; collection is not falsely promoted to a usable recommendation.

## Waiver collection — cadence and reconciliation

Baseline: merged PR #22, `75e577eee3cec0a58a0ebbdca01c1a3a7d2b584b`; post-merge CI `37130397673` passed the release gate and committed-dist synchronization.

The waiver wrapper now requests Berlin time: Tuesday–Thursday at 00:17, 04:17, 08:17, 12:17, 16:17 and 20:17; Friday–Monday at 08:17. GitHub's IANA timezone scheduling preserves the local day/hour through DST. Queue delays remain possible; archived timestamps reflect actual observation after each transaction response. January 1–11 uses four-hour workflow polls with non-08:00 Fri–Mon capture slots skipped before source requests. This avoids restricted day-of-month/day-of-week cron OR semantics accidentally scheduling January 12 onward. No waiver cron covers January 12–August 31; post-draft preseason activation and the global all-workflow blackout transition remain separate calendar work. Manual dispatch remains available.

The collector defaults to the current Sleeper transaction round plus two prior rounds, bounded at round 0. Preseason stays round 0 instead of becoming Week 1. Manual `--weeks` and `--round-lookback` remain explicit controls. Known requested/profile/live season mismatches fail before incorrectly labeling observations as another season.

Automatic daily observations record their Berlin capture date and portfolio count. Serialized jobs check the newest main checkout and suppress a second Fri–Mon capture on that date, including delayed January polls. A manual/scoped observation does not falsely suppress an automatic full-portfolio capture. The same receipt rule applies to reruns in September–December. Tue–Thu continues to collect at each scheduled opportunity.

New immutable source envelopes also retain the users response. Roster budgets use the live observed league cap; missing responses remain source failures. Missing/malformed transaction responses no longer crash on `len(None)` or become evidence of an empty bid book. Pending, processed and failed claims remain as exposed; an unspecified failure is not relabeled as an outbid. Source errors and observation times appear in invocation diagnostics. A successful capture with failed inputs is explicitly `PARTIAL_SOURCE_FAILURE`.

Each league gets an additive `reconciliations/<league_id>/reconciliation_<timestamp>.json` within its season directory. Identity is season + league + transaction ID. Repeated responses/round overlap do not duplicate transactions; distinct raw transaction content has hash-bound observed revisions and retained source references. Later empty or failed responses do not erase an earlier observed claim. Cutoff filtering excludes later observations. Creator names are bound to the captured users response; unresolved IDs remain explicit. The latest view means last observed response, not provider finality. Validators authenticate revision and latest-transaction fields against immutable source bytes. First-write archives remain untouched.

The reusable workflow keeps separate waiver/weather paths, skips only automatic waiver captures outside their window, reports the exact invocation's output-index artifact, validates reconciliation, and adds one bounded push retry. The collector/reconciler/validator/test are manifest-bound; the new focused test is part of the release gate. Weather collection remains on its existing schedule.

This sample contains no distinct transaction revisions; pending/processed corrections and idempotence are demonstrated by regression fixtures. The 12 new capture files and one derived reconciliation are preserved under `data/research/waivers/sleeper/2026`; no earlier capture is rewritten. The complete waiver validator accepts 1,153 source envelopes.

This is collection infrastructure, not a scoring/model repair or waiver-economics change. Reconciled claims remain `decision_model_eligible: false`; private absent bids remain unknown. These archives do not feed contemporaneous observed bids into their own recommendations. Offensive next-three-week projection blockers remain unchanged.
