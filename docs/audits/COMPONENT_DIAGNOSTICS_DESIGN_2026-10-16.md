# Component diagnostics and challenger interface — frozen implementation contract

The user approved implementing parameter tracking, error decomposition and a
separate chronological challenger interface. The existing model remains the
baseline. New learned weighting/feature-selection methodology is NOT trained by
this change; its interface explicitly requires the repository statistical-method
checkpoint before a candidate grid, fitting or selection is enabled.

The adapter runs outside the sealed standalone recovery owner. It writes only
new operational run paths. Snapshots bind fit/config/source hashes, retain actual
support, and compare only identical methodology versions and non-future cutoffs.
Team/position/status changes are separate context events. Zero support is PRIOR_ONLY,
not proof of a learned defensive effect. Fixed method weights are documented
configuration constants, not learned or statistically optimal estimates.

Raw component errors have sign forecast minus actual. For multiplicative chains,
the average incremental contribution over every ordering of factors sums exactly
to the total error. Forecast ratios are implied ratios of projected means, not
claims that they equal underlying fitted conditional parameters. Zero parent
opportunities leave efficiency unidentified; no fake zero efficiencies are
inserted. Missing factors stay unknown. Team volume/player share is used only
when actor-budget coverage is complete and observed team membership agrees with
the cutoff team; otherwise player-opportunity decomposition remains separate.
All decompositions are postgame explanations, never accuracy-eligible forecasts.

Ranks use the frozen component forecast within model/position/week. Actual
outcomes never choose rank groups. Reports retain all rows, including zero-role
players, and show opportunity-supported cohorts separately. Aggregation is by
position, team, pregame rank and lead week. League scoring does not multiply the
underlying football sample count. Probability components receive Brier and
reliability diagnostics only with observed binary labels.

Known schema issue found while building this tracker: the preserved V2 source
refitter expects `opponent`, but its captured player-week source publishes
`opponent_team`. The saved source-refit has zero observed support in all 96
RB/TE/WR, 96 WR-tier and 64 QB/RB rushing defensive groups. Team-level opponent
PBP effects are separate. The tracker MUST expose these prior-only cells.
An explicit V3 adapter normalizes the column and creates a NEW fitted artifact;
it must not overwrite the saved V2 fit, archived reports or issued projections.
Future weekly fresh fits use the explicitly labelled V3 source-adapter repair.
This is a source-schema bug fix, not learned weight selection or an automatic
model-promotion decision. Archived V2 replay uses its original fit unchanged.

Outputs: parameter rows, fit-to-fit changes, context changes, support summary,
component decompositions, team/rank/position/lead metrics, probability diagnostics,
league component error contributions, HTML report, and source-bound receipts.
Initial W6-8 reports remain pending until matching actuals exist. Real W5 data
and synthetic controlled examples test wiring without inventing W6 accuracy.
