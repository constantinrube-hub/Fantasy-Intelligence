# FIE V9.3.1 Completion Patch: Upload and Validation

This is an overlay patch for the existing V9.3 repository. It contains only files changed or added by the completion pass. Do not delete the rest of the repository.

## What this patch completes

1. Persistent browser caching for stable shared NFL/projection proxy data, with live league state kept network-fresh.
2. Progressive league loading semantics, with public enrichment included in background-completion status rather than blocking core interaction.
3. One canonical structural replacement/scarcity path driven by league starter slots, FLEX/Superflex eligibility and structural bench demand, not by the selected user's roster.
4. Best Ball-specific Draft Board profile, Draft Assistant Portfolio Fit estimate, and Team Contribution Profile behavior.
5. V9.3.1 release metadata and deterministic regression coverage.
6. A dedicated GitHub validation workflow that rebuilds the deploy artifact and reruns the complete source release gate.

## Upload

Upload the ZIP contents at the repository root, preserving all paths. Existing files with the same path should be replaced. New files should be added. Do not replace the repository with only the patch contents.

Recommended GitHub approach: create a short-lived branch such as `v9.3.1-completion`, overlay the patch, then merge after validation. Uploading directly to `main` is also supported if you prefer the current workflow.

## Required validation order after upload

### 1. Validate FIE V9.3.1 Completion

GitHub → Actions → **Validate FIE V9.3.1 Completion** → **Run workflow**.

Required outcome:
- workflow is green;
- `config/release-gate.json` in the uploaded Actions artifact reports `DEPLOYABLE_SOURCE`;
- every recorded check has `ok: true`;
- `browser_preview_required` remains `true`, which is intentional until manual live preview is complete.

### 2. Refresh FIE Current Season

After the validation workflow passes, run **Refresh FIE Current Season**.

Recommended inputs:
- `league_id`: leave blank to refresh every enabled managed league;
- `season`: blank;
- `week`: blank;
- `governance_mode`: `KEEP` for the first post-patch run.

This confirms the V9.3.1 runtime/integrity tests in the same workflow that refreshes the 19 live current stores.

### 3. Do not run the full M1-M6 historical research workflow merely to validate V9.3.1

**Build FIE Research Milestones 1-6** is much heavier and can alter research artifacts. Run it only when a league's research bundle is stale/missing or when you intentionally want to rebuild milestone research. It is not required for this UI/runtime completion patch.

### 4. Optional market freshness

Run **Capture Immutable FIE Market Benchmark** only if you want a new market/ADP benchmark snapshot. It is not required to prove this patch is correct.

## Required browser preview before production sign-off

Check at minimum:

- Genesis Dynasty: `C0nstant1n` auto-selected, Kicker and D/ST supported, legal position filtering correct.
- Chopped – Drive: Value Finder opens without crash, Chopped Draft Board is short-horizon oriented, Dynasty Buy Targets absent.
- One 1QB and one Superflex league: Draft/Scarcity diagnostics show materially deeper QB demand/replacement in Superflex without changing when you switch the selected roster.
- One Best Ball league: Draft Board shows `Ceiling / Profile`, Draft Assistant shows `Portfolio Fit *`, Team shows `Contribution Profile`.
- Weekly: Max Points and opponent-aware Max Win modes both work; matchup/simulation is housed here rather than Team/Waivers.
- Waivers: rows are complete Add → Drop transactions and FAAB is clearly an estimate where not governed.
- Trade Center: legality is based on the final post-trade roster.
- Players: league-illegal positions are hidden by default and FAAB Strategy is absent.
- Performance: initial league workspace becomes usable before background enrichment finishes; revisiting shared data after a reload should increase persistent-cache hits in Runtime & Data Quality.

## Production metadata

V9.3.1 intentionally remains `stage: release-candidate` until the browser preview above is complete. After that preview passes, promotion to `production` should be a small metadata-only change, not another functional rewrite.
